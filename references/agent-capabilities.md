# Route work by available capabilities

Inspect current tool access, local runtime, browser, fonts, media, and export dependencies before committing to a concept. Agent names do not prove access to any capability. Do not claim integrations that were not exercised.

| Need | Prefer | Without that capability |
| --- | --- | --- |
| Product evidence | Existing captures or read-only browser inspection | Supplied evidence, clearly marked reconstruction |
| Exact layout, labels, state changes | React/SVG and real UI assets | Simplify the scene without changing claims |
| Original subject, material, environment | Available built-in image generation/editing | Real assets or code-native construction |
| Consistent generated assets | Shared reference images and targeted edits | Fewer generated assets and a simpler world |
| Motion requiring changing anatomy or viewpoint | Available video generation with established budget | Editable motion, licensed footage, or another shot |
| Repeatable export | Frame-driven local Remotion | Documented HTML ready/seek fallback |
| Quality evidence | Encoded-frame inspection plus separate listening | State which review remains unperformed |

## Codex

Use the current built-in image generation tool when available, following its imagegen skill. Generate a few informative key assets, inspect them, and copy selected outputs into the production project's public directory. Do not refer to session-only generated paths in a delivered project. Use transparent output for independent cutouts; inspect local images before requesting edits. Never silently substitute a paid API for an unavailable built-in tool.

Use local code for composition and deterministic motion. Browser access gathers evidence; screenshots do not establish that a navigation sequence was recorded. Generated video is optional and must have a shot-specific reason plus an existing cost boundary; otherwise choose a feasible alternative. No new paid service is a baseline dependency.

Maintain a production record of tool availability, why each asset route was chosen, failures or substitutions, and review actually performed. Only parallelize independent asset work; concept selection and reference-dependent edits remain sequential.

## Motion graphics

For selections, object relationships, transformations, and kinetic type, prefer frame-driven React/SVG choreography when available. Read [MG recipes](motion-graphics.md). A code-capable agent can author and render original motion systems; verify tools rather than assigning abilities by agent brand. Image generation is optional here and should not replace controllable objects with a flat poster.
